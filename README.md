# AI Code Detector

AI Code Detector is a web application and API for analyzing whether a source-code snippet is likely written by a human or generated by AI. The project is based on the SemEval-2026 Task 13 setting and currently supports three prediction subtasks using locally stored UniXcoder-based models.

## Current Status

This repository is an active development project. The core backend inference API and React web interface are implemented. Authentication, Docker deployment, file upload, batch scanning, and span-level highlighting are planned but not implemented yet.

## Features

- Detect whether code is human-written or AI-generated.
- Attribute AI-generated code to a likely model family.
- Classify code style as human, machine, hybrid, or adversarial.
- Display prediction confidence in a web UI.
- Store recent analysis history in browser local storage during the current session.
- Download prediction results as JSON from the browser or backend.

## Model Tasks

| Task | Purpose | Labels |
| --- | --- | --- |
| Subtask A | Binary code-origin detection | `Human`, `AI` |
| Subtask B | Generator-family attribution | `Human`, `DeepSeek-AI`, `Qwen`, `01-ai`, `BigCode`, `Gemma`, `Phi`, `Meta-LLaMA`, `IBM-Granite`, `Mistral`, `OpenAI` |
| Subtask C | Generation-style classification | `Human`, `Machine`, `Hybrid`, `Adversarial` |

The current models are fine-tuned from `microsoft/unixcoder-base` and loaded from:


## Setup And Run

From the repository root, run:

```bash
./run_project.sh
```

The script starts all required local services:

- MongoDB on `mongodb://127.0.0.1:27017/`
- FastAPI backend on `http://localhost:8000`
- React frontend on `http://localhost:5173`

It also opens the frontend in your browser.

MongoDB data and logs are stored locally under:

```text
.local/mongodb/data
.local/mongodb/log/mongod.log
```

Backend API documentation is available at:

```text
http://localhost:8000/docs
```

If this is the first time running the project, make sure dependencies were installed once:

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cd ../web
npm install
```

After that, day-to-day startup only needs:

```bash
./run_project.sh
```

## Startup Script

`run_project.sh` performs these steps:

- Creates local MongoDB data/log directories if needed.
- Starts `mongod` with `--dbpath .local/mongodb/data`.
- Starts the FastAPI backend in a new terminal.
- Starts the React frontend in a new terminal.
- Opens `http://localhost:5173`.

Note: this script is intended for a local Linux desktop environment with `gnome-terminal`, `mongod`, `mongosh`, and `xdg-open` installed.

If MongoDB fails to start, check `.local/mongodb/log/mongod.log`.

## API Endpoints

### Health Check

```http
GET /health
```

Example response:

```json
{
  "status": "ok",
  "available_models": ["subtask_a", "subtask_b", "subtask_c"]
}
```

### Predict All Tasks

```http
POST /predict-all
```

Request body:

```json
{
  "code": "def add(a, b):\n    return a + b",
  "language": "python"
}
```

Example response:

```json
{
  "input": {
    "language": "python",
    "code": "def add(a, b):\n    return a + b"
  },
  "predictions": {
    "subtask_a": {
      "label": 1,
      "prediction": "AI",
      "confidence": 0.91,
      "summary": "AI - 91.00%",
      "probabilities": {
        "Human": 0.09,
        "AI": 0.91
      }
    }
  }
}
```

When all three models are available, the `predictions` object contains `subtask_a`, `subtask_b`, and `subtask_c`.

### Download Backend JSON

```http
POST /predict-all-json
```

This endpoint runs the same prediction pipeline, writes a JSON file under `outputs/`, and returns it as a downloadable file.

## Frontend Workflow

1. Paste source code into the input area.
2. Select the programming language.
3. Click `Analyze Code`.
4. Review prediction cards for each available subtask.
5. Optionally show raw JSON or download the result.

The current UI stores history using browser local storage under the key:

```text
analyze_history
```

## Training Notebooks

Training experiments are stored in `Notebook/`.

The notebooks fine-tune `microsoft/unixcoder-base` for the SemEval subtasks and export Hugging Face-compatible model folders containing files such as:

- `config.json`
- `model.safetensors`
- `tokenizer.json`
- `tokenizer_config.json`
- `id2label.json`
- `label2id.json`
- `model_meta.json`

Validation metrics saved in the model metadata:

| Task | Validation Accuracy | Validation F1 |
| --- | ---: | ---: |
| Subtask A | 0.9964 | 0.9964 |
| Subtask B | 0.9514 | 0.6302 |
| Subtask C | 0.9175 | 0.8745 |

## Limitations

- Predictions are probabilistic and should not be treated as absolute proof of authorship.
- Very short code snippets may produce unreliable predictions.
- Edited AI-generated code can be harder to classify correctly.
- Model-family attribution is approximate.
- The selected programming language is currently included in the response but is not used by the model inference logic.
- The backend truncates input to 512 tokens during model inference.

## Development Notes

- Backend CORS currently allows `http://localhost:5173` and `http://127.0.0.1:5173`.
- Frontend API base URL is currently hardcoded in `web/src/api/predictApi.js`.
- Model folders are required at runtime. If no valid model folder is found, the API returns an error instead of predictions.
- The repository `.gitignore` ignores model/checkpoint folders, so model weight tracking should be decided deliberately before publishing.
